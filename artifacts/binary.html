From bits to networks

Every IP address, subnet mask, and routing decision on a network is a string of 32 binary digits underneath. This walks through the conversion, step by step, with a live playground you can wire up with real numbers.

01basics

Why networking runs on binary

Computers address, route, and filter traffic using pure binary — every IP address is really a 32-bit number. We write it as four decimal numbers (octets) separated by dots only because that's easier for humans to read. Each octet is 8 bits, and each bit position is worth a fixed value.

To convert binary → decimal, add up the place values wherever there's a 1. To convert decimal → binary, work from 128 down: if the number is ≥ the place value, put a 1 and subtract it; otherwise put a 0 and move on.

04subnetting

Subnet masks & CIDR playground

A subnet mask splits those 32 bits into two zones: network bits (which network this address belongs to) and host bits (which specific device on that network). The CIDR number — the /24 in 192.168.1.10/24 — is just a count of how many leading bits are network bits.

enter an ip and slide the cidr

Orange bits are locked to the network — every device sharing this subnet has the same orange pattern. Teal bits are free for host addresses. Fewer teal bits means a smaller subnet with fewer usable devices, but more subnets overall.

06implementation

Putting it into a router

Once the binary math is planned, configuring it on real equipment (a home router, a Cisco switch, or a Linux box) follows the same handful of steps:

  • 1
    Pick the block and CIDR Decide the address range and prefix length, e.g. 192.168.1.64/26, based on how many hosts that segment actually needs.
  • 2
    Convert /26 to a dotted mask 26 network bits → 11111111.11111111.11111111.11000000 → 255.255.255.192. This is the exact value you type into the "subnet mask" field.
  • 3
    Assign the gateway Give the router's interface for that segment the first usable address, e.g. 192.168.1.65, and set it as the default gateway for devices on that subnet.
  • 4
    Configure DHCP or static addressing Restrict the DHCP pool to the usable range (.66 – .126) so it never hands out the network or broadcast address.
  • 5
    Add the route Make sure the routing table has an entry for 192.168.1.64/26 pointing at the right interface so other subnets can reach it.
  • 6
    Verify From a host on the segment, confirm its IP and mask with ipconfig / ip addr, then ping the gateway and a device on another subnet to confirm routing works as planned.
