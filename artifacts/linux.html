01 — orientation

What Linux is, in practice

Linux is the kernel — the core piece of software that talks to your hardware — at the center of a whole family of free operating systems. Unlike Windows or macOS, no single company owns it. Instead, different groups package the kernel together with their own set of tools, defaults, and design philosophy, and each finished package is called a distribution, or "distro" for short. That's why "Ubuntu," "Fedora," and "Arch" all mean "Linux" but feel like different operating systems.

Three ideas make everything else click:

  • The terminal is a first-class citizen. Almost anything you can do with a mouse, you can do faster with a typed command. This isn't a power-user afterthought — it's the native interface.
  • The filesystem has one root. There's no C: drive. Everything — your files, connected drives, your programs — lives somewhere under a single /, with folders like /home (your personal files), /etc (configuration), and /var (logs, changing data).
  • Software comes from repositories, not websites. Instead of downloading installers, you ask a package manager — apt, dnf, pacman, depending on the distro — to fetch and install (and later update) software for you.
first commands worth knowing
pwd                 # where am I?
ls -la               # what's here?
cd Documents         # go somewhere
sudo apt update      # refresh the list of available software
sudo apt install htop  # install something (Debian/Ubuntu family)
man ls               # read the manual for any command

sudo is worth calling out on its own: it temporarily runs a single command with administrator privileges. You'll type it constantly for anything that touches system files — it's Linux's equivalent of the "Run as Administrator" prompt, except scoped to one command instead of a whole session.

02 — running it alongside Windows

Getting Linux running on Windows

You have four realistic paths, in order of how much they disturb your existing setup.

WSL2 recommended for most people

Windows Subsystem for Linux runs a real Linux kernel directly alongside Windows — no separate boot, no dedicated disk partition, and file access works in both directions.

  1. Open PowerShell as Administrator and run wsl --install.
  2. Restart when prompted.
  3. On relaunch, choose a distro (Ubuntu is the default) and set a username and password.
  4. Launch it anytime from the Start menu, or type wsl in any terminal.

Virtual machine safest to experiment in

Install VirtualBox or VMware Workstation, download a distro's .iso installer image, create a new virtual machine, and install Linux inside it exactly as if it were a physical computer. Windows never sees a single file change.

  1. Install VirtualBox (free) from its official site.
  2. Download an ISO — Ubuntu Desktop is a solid first choice.
  3. In VirtualBox: New → allocate RAM (4GB+) and disk (25GB+) → attach the ISO → start.
  4. Walk through the on-screen installer as you would for any OS.

Dual boot best real-hardware performance

Linux installs onto its own disk partition alongside Windows, and a boot menu lets you choose which OS to start each time. Full hardware speed, but back up your data first — partitioning carries real risk if interrupted.

  1. Shrink your Windows partition in Disk Management to free up unallocated space.
  2. Write a distro's ISO to a USB drive with Rufus or balenaEtcher.
  3. Boot from the USB (via your BIOS/UEFI boot menu) and choose "install alongside Windows."
  4. Reboot — GRUB, the boot menu, now lets you pick an OS at startup.

Live USB zero commitment

Boot Linux entirely from a USB stick with nothing installed to your hard drive at all. Perfect for a test drive.

  1. Write an ISO to USB with balenaEtcher.
  2. Restart your PC and enter the boot menu (commonly F12, Esc, or F2).
  3. Select the USB drive and choose "Try [distro]" rather than "Install."
03 — running it alongside macOS

Getting Linux running on a Mac

Macs don't have a WSL equivalent, and Apple Silicon (M-series) Macs can't dual-boot Linux the way Intel Macs once could — but virtualization is fast and well-supported on both chip types.

UTM free, native on Apple Silicon

UTM wraps Apple's own virtualization framework in a friendly interface, and runs ARM Linux distros at near-native speed on M-series Macs.

  1. Install UTM from utm.app or the Mac App Store.
  2. Download the ARM64 build of a distro (Ubuntu Server or Debian are easy first picks).
  3. In UTM: Create a New VM → Virtualize → attach the ISO → allocate RAM/disk → start.
  4. Install as normal from the guided installer.

Parallels Desktop paid, most polished

Parallels is commercial software, but it offers one-click Linux distro downloads, shared folders with macOS, and clipboard sharing out of the box.

  1. Install Parallels Desktop and open it.
  2. Choose "Download Linux" or "Install from image" in the new-VM wizard.
  3. Follow the prompts — Parallels handles most configuration automatically.

Docker Desktop for running Linux software, not a desktop

If your goal is really "I want to run Linux-based tools and servers," not "I want a Linux desktop," Docker gives you isolated Linux environments without managing a full VM yourself.

  1. Install Docker Desktop for Mac.
  2. Run docker run -it ubuntu bash to drop into a live Ubuntu shell.
a note on Intel vs Apple Silicon
Intel Macs can also dual-boot older Linux distros using rEFInd as a boot manager, though this path is less common now than it used to be. On M-series Macs, virtualization is the practical route — the hardware simply doesn't support the older dual-boot method.

06 — build something

Turning Linux into a personal server

"Server" just means a machine that stays on and answers requests — from your other devices, or from the internet. It can be a repurposed old laptop, a Raspberry Pi, a mini PC, or a virtual machine. The distro of choice here is usually a lightweight, no-desktop build like Ubuntu Server or Debian, since a server rarely needs a graphical interface at all.

What you can actually build with it

File server / home NAS

Share and back up files across every device on your network using Samba or NFS — your own private Dropbox, with no storage limit but your own drive.

Media server

Run Jellyfin or Plex to stream your own movies, shows, and music to any TV or phone in the house, organized and searchable.

Personal website or web app

Host a blog, portfolio, or side project with Nginx or Apache, fully under your control instead of a third-party platform.

Home automation hub

Run Home Assistant to tie together smart bulbs, sensors, and switches from different brands into one local dashboard.

Private VPN

Set up WireGuard so you can securely reach your home network — and route your traffic through it — from anywhere.

Game server

Host a Minecraft, Valheim, or CS2 server for friends, with full control over mods, uptime, and who's invited.

Ad and tracker blocking

Run Pi-hole to filter ads and trackers network-wide, for every device that connects — no per-device app needed.

Development sandbox

A always-on Linux box to test code, run CI jobs, or host databases without touching your main computer.

A minimal first setup

# after installing Ubuntu Server, from another machine:
ssh youruser@server-ip-address

# keep it updated
sudo apt update && sudo apt upgrade -y

# install something useful — e.g. a file share
sudo apt install samba

# check what's listening on the network
sudo ss -tulpn
before you expose anything to the internet
Give the server a static local IP, enable a firewall (ufw is the simplest option on Debian-based systems), and only open the specific ports each service actually needs. A server reachable from outside your home network is worth locking down deliberately, not by default settings.
07 — the case for it

What running your own server actually gets you

1
Ownership of your own data

Photos, files, and media live on hardware you control, not on a company's servers subject to their pricing changes, outages, or policy shifts.

2
No recurring subscription creep

One machine can replace several monthly subscriptions — cloud storage, streaming-media apps, VPN services, smart-home clouds — with a single upfront cost.

3
A real place to learn

Networking, security, backups, and troubleshooting stop being abstract concepts once a service you actually use depends on you keeping it running.

4
Flexibility to grow

Start with one small service, and the same box can quietly pick up more roles over time — file sharing today, a game server or home automation hub next month.

5
Works even when the internet doesn't

Local-network services keep running during an outage, since nothing has to leave your house to reach another device on the same network.

08 — virtualization

Operating a virtual system

Virtualization lets one physical machine pretend to be several. Instead of buying separate hardware for every server or experiment, you carve one computer's CPU, memory, and storage into isolated slices — each one behaving like its own independent machine.

Type-2 hypervisors
run inside a host OS

VirtualBox, VMware Workstation, and UTM run as ordinary applications on top of Windows, macOS, or Linux. Easiest to start with — good for testing a distro, running an isolated environment, or the "on Windows/Mac" paths described above.

Type-1 hypervisors
run directly on hardware

Proxmox VE and bare-metal ESXi install directly onto a machine with no host OS underneath them at all — the hypervisor is the operating system. This is how you turn a dedicated box into a small private cloud, running several virtual machines and containers side by side, each with guaranteed resources and its own network identity.

Containers
lighter than a full VM

Docker and LXC don't emulate a whole computer — they isolate a process using the host kernel's own features. Faster to start, lighter on resources, but less isolated than a true VM. Ideal for running many small services (a web app, a database, a bot) on one server without each one needing its own full OS copy.

Operating one day-to-day

  • Snapshots — save a VM's exact state before making a risky change, and roll back instantly if it breaks.
  • Resource allocation — assign each VM a fixed share of CPU cores, RAM, and disk so one guest can't starve the others.
  • Networking modes — bridged (the VM gets its own address on your network) versus NAT (the VM shares the host's address) changes whether other devices can reach it directly.
  • Headless operation — most server VMs run without a display at all; you manage them entirely over SSH or a web console like Proxmox's.
# quick example: spin up an Ubuntu VM from the command line with QEMU
qemu-img create -f qcow2 myserver.qcow2 20G
qemu-system-x86_64 -m 2048 -hda myserver.qcow2 -cdrom ubuntu-server.iso -boot d
why this matters for a personal server
Virtualization means one physical box can safely host your file server, media server, and a test environment for new projects at the same time — each isolated, so a crash or misconfiguration in one never touches the others.
