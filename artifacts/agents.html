01 — THE STACK

What an agent is actually made of

An "AI agent" is a loop: a model that reasons, a set of tools it can call, memory that persists across steps, and a runtime that keeps the loop honest. Everything below fills one of those roles.

Reasoning — the model

The LLM doing the planning and tool-calling. Pick by cost-per-task, not benchmark bragging rights.
Claude APIStrong tool-use and long-context reasoning; usage-based pricingpay-per-token
GPT / OpenAI APIBroad ecosystem support, realtime and voice optionspay-per-token
Local open modelsLlama / Qwen / Mistral via Ollama — no per-call cost, needs a GPUself-hosted

Orchestration — the loop

The framework that wires model, tools, and state together into a controllable agent instead of a one-shot prompt.
LangGraphStateful, graph-based orchestration; the current default for production agentsopen source
CrewAIRole-based multi-agent crews, fast to prototypeopen source
Provider agent SDKsOpenAI Agents SDK / Claude Agent SDK — thin, provider-native primitivesopen source
n8n / MakeVisual, node-based automation — no code required to wire an agent into workflowsfreemium

Memory — state that persists

Short-term scratch space plus a long-term store the agent can search back through.
SQLite / PostgresStructured state — tasks, conversation logs, business recordsself-hosted
Chroma / pgvectorVector store for semantic recall (RAG)open source
Pinecone / Weaviate CloudManaged vector DB — no ops, scales without you touching inframanaged

Tools — what the agent can act on

The hands. An agent without tool access is just a chat window.
MCP serversStandardized connectors — email, calendar, CRM, file systems, browsersopen protocol
Zapier / ComposioThousands of prebuilt app integrations, callable as agent toolsfreemium
Browser automationPlaywright / browser-use — for agents that need to click around the webopen source

Runtime & deployment

Where the agent actually lives and runs when nobody's watching.
Local / cronA laptop or a $6/mo VPS running on a schedule — fine for early testingself-hosted
Docker + a cloud VMPortable, predictable, cheap at small scale$5–40/mo
Serverless (Modal, Fly, Cloud Run)Pay only while the agent is actually thinkingusage-based

Observability — knowing what it did

Non-negotiable once an agent is spending your money or talking to customers unsupervised.
LangSmith / LangfuseFull run traces, token spend, evaluation datasetsfreemium
Plain loggingStructured logs to a file or DB — the free floor, better than nothingDIY
02 — BUDGET

Low-end vs. high-end builds

The gap between these two setups is mostly reliability, scale, and how much of the babysitting is automated away — not whether the agent works at all.

LOW-END
$0–30/month
One founder, one laptop, one idea to validate
  • Model Free-tier API calls or a local open model on your own GPU
  • Framework LangGraph or CrewAI, self-hosted, default config
  • Memory SQLite file + local Chroma index
  • Tools A handful of MCP servers or hand-rolled API calls
  • Hosting Runs on your machine or a $5–6/mo VPS on a cron job
  • Monitoring Print statements and a log file
  • Ceiling Fine for one agent, one workflow, low request volume
HIGH-END
$2,000+/month
Small team, production traffic, real customers depending on it
  • Model Frontier model API at volume, plus a cheaper model for routine steps
  • Framework LangGraph Platform or an equivalent managed orchestration layer
  • Memory Managed Postgres + managed vector DB (Pinecone / Weaviate)
  • Tools Paid integration platform (Zapier/Composio) plus custom MCP servers
  • Hosting Autoscaling serverless or a small Kubernetes cluster
  • Monitoring LangSmith/Langfuse with alerting, evals, and human-review queues
  • Ceiling Multiple agents, high concurrency, SLA-grade uptime
WHERE THE MONEY ACTUALLY GOES Model API calls dominate cost at any scale before infrastructure does. Prototype on a cheap or local model, and only upgrade the model once the workflow itself is proven — not before.
03 — NEW VENTURES

Agent categories that can run as a self-sustained business

Agents where the product is the automation — the business model is charging for output the agent produces with little ongoing human labor.

01

Content & SEO agents

Research a niche, draft and publish articles, monitor rankings, and iterate on what performs — sold as a subscription service to small sites.

niche blogs · newsletter mills · programmatic SEO
02

Research & data agents

Continuously scrape, summarize, and structure a category of information (competitors, prices, regulations) and sell access to the feed.

market-intel feeds · price trackers · lead lists
03

Customer support agents

A packaged support bot other businesses install — the business is the packaging, pricing, and reliability layer, not any single deployment.

helpdesk-as-a-service · onboarding bots
04

Personal & niche assistants

A vertical assistant for one narrow job — meal planning for a diet type, scheduling for a specific profession, expense sorting for freelancers.

vertical SaaS copilots
05

Trading & monitoring agents

Watches a market or dataset and acts or alerts on defined rules. High technical and financial risk — treat as a research project first, a business second.

alert bots · rules-based execution
06

Creative production agents

Generates and assembles a specific creative output at volume — short-form video edits, product mockups, ad variants — sold per output or per seat.

social clip factories · ad-variant generators
04 — EXISTING OPERATIONS

Agent categories that augment a business you already run

Here the agent isn't the product — it's headcount you don't have to hire, embedded into work that's already happening.

A

Inbox & scheduling agents

Triages email, drafts replies, and finds meeting times, so the first pass of admin work never touches a human.

reduces founder/ops-lead admin load
B

Sales & outreach agents

Qualifies inbound leads, personalizes outreach at scale, and updates the CRM automatically after every call or email.

pipeline never goes stale
C

Support & FAQ agents

Handles the repetitive slice of support tickets and escalates only what genuinely needs a person.

cuts response time, not headcount trust
D

Finance & ops agents

Reconciles invoices, flags anomalies, chases overdue payments, and keeps books current between accountant check-ins.

bookkeeping copilot, not replacement
E

Internal knowledge agents

Answers "where's the doc for X" against your own wiki, contracts, and past decisions instead of a colleague's memory.

RAG over internal docs
F

QA & monitoring agents

Watches logs, uptime, or output quality and opens a ticket — or fixes the obvious cases — before a customer notices.

on-call agent for small teams
05 — SEQUENCE

The order to actually build in

Same sequence whether the budget is $0 or $20,000 — only the tooling at each step changes.

Pick one narrow job, not a "platform"

Define a single task with a clear success condition before touching a framework. Broad "does everything" agents are where most builds stall.

Wire the loop by hand first

A model call, one or two tools, and a while-loop teach you more about failure modes than any framework's abstractions will.

Add memory only once the task needs it

Most early agents don't need a vector database. Add persistence when you can point at the specific step that requires recall.

Introduce a framework once the loop outgrows hand-rolling

Move to LangGraph, CrewAI, or a provider SDK when state, retries, and multi-step planning get too fiddly to manage manually.

Put guardrails in before real usage

Spend limits, human approval on irreversible actions, and logging — all before the agent touches a live customer or a real account.

Deploy small, watch closely, then scale the budget

Run it on the cheap tier under real conditions first. Only move to managed infrastructure once volume or reliability actually demands it.

Tool and pricing details reflect the landscape as of 2026 and shift quickly — check current pricing before committing a budget. Treat every "self-sustained business" category above as an idea worth testing small, not a guaranteed outcome.
