How networks are wired — and how data actually moves through them.

Two questions sit under almost everything in networking: how are the devices physically or logically connected (topology), and how does data travel between them (TCP vs UDP). This page walks through both with diagrams, plainly.

01

What "network topology" actually means

A topology is just the layout — the pattern of connections between devices on a network. It answers: which device is wired to which other device, and by extension, what path does data have to take to get from one machine to another?

Topology matters for three practical reasons: it determines cost (how much cable or hardware you need), resilience (what happens when one connection fails), and performance (how much traffic can move at once without collisions). Every layout below is a different trade-off between those three things.

02

The six topology types

Real networks are almost always a mix of these, but each pattern below is a distinct building block worth recognizing on its own.

Bus

legacy / rare today

Every device taps into a single shared cable (the "backbone"). Data travels the whole line, and each device checks whether a message is addressed to it.

CABLE USE
Minimal — one shared line
FAILURE MODE
One break kills the whole segment

Star

most common today

Every device connects individually to one central point — a switch or router. That hub relays everything. This is how nearly every home and office network is wired now.

FAILURE MODE
One cable dies, only that device drops
WEAK POINT
Hub fails → entire network goes down

Ring

niche / industrial

Each device connects to exactly two neighbors, forming a closed loop. Data passes from device to device around the ring until it reaches its destination.

TRAFFIC FLOW
Predictable, one direction
FAILURE MODE
One break can split or halt the loop

Mesh

high resilience, high cost

Every device connects directly to every other device. There's no single point of failure — if one link goes down, traffic just reroutes through another.

RESILIENCE
Highest — many redundant paths
COST
Scales fast: 5 devices = 10 links

Tree

used to scale star networks

A hierarchy of star networks: one root hub feeds several secondary hubs, each of which feeds its own group of devices. This is how most large offices and campuses scale up.

SCALABILITY
Easy to add new branches
WEAK POINT
Root or branch hub failure cuts off everything below it

Hybrid

what real networks look like

A mix of two or more topologies stitched together — say, a mesh core for reliability with star segments feeding off it for individual offices. It takes the best-fit piece of each pattern for the part of the network that needs it.

IN PRACTICE
Nearly every real-world network
TRADE-OFF
More complex to plan and maintain
03

TCP and UDP — the two ways data travels

Once devices are wired together, something has to govern how the actual data gets chopped up, sent, and reassembled. That's the job of the transport layer — and almost all of it comes down to two protocols.

TCP

Transmission Control Protocol — reliable, ordered

TCP starts every connection with a three-way handshake (shown above) before a single byte of real data moves. Once connected, it numbers every piece of data, waits for confirmation it arrived, and resends anything that got lost.

  • Ordered: data arrives in the exact sequence it was sent, even if packets took different routes.
  • Reliable: lost packets are automatically detected and re-sent.
  • Flow-controlled: the sender slows down if the receiver can't keep up.
  • Trade-off: all that checking adds delay — TCP is accurate, not fast.

UDP

User Datagram Protocol — fast, no guarantees

UDP skips the handshake entirely — it just fires data ("datagrams") at the destination and moves on. Nobody checks it arrived, nobody re-sends it if it doesn't, and nobody guarantees the order.

  • No setup delay: data starts flowing immediately, no handshake needed.
  • No delivery guarantee: lost packets just stay lost.
  • No ordering: packets can arrive in a different order than they were sent.
  • Trade-off: UDP is fast precisely because it doesn't check anything.

05

When each one gets used

In practice, the choice usually isn't made by the end user at all — it's baked into the application. But knowing which is which explains a lot about why some things behave the way they do.

TCP is used for →
  • Loading web pages (HTTP/HTTPS)
  • Sending and receiving email (SMTP, IMAP)
  • Transferring files (FTP)
  • Anything where a missing byte would corrupt the result
UDP is used for →
  • Live video and voice calls
  • Online multiplayer games
  • Live-streaming broadcasts
  • DNS lookups (quick, single-shot requests)
