MOBILE APP DEPLOYMENT — REFERENCE

Three platforms. Three pipelines. One shared finish line.

Android, iOS, and the mobile web each test and ship differently — different tools, different gatekeepers, different paperwork. This page lines the three pipelines up side by side: how you test a build, how you submit it, what tools the work actually requires, and what rights or agreements you need before anyone outside your team can install it.

$ ./gradlew bundleRelease  &  upload to Play Console
$ xcodebuild archive  &  xcrun altool --upload-app
$ npm run build  &  deploy to CDN — no review queue

02

Testing, step by step

Each pipeline has its own pre-release gate — from local emulators to mandatory tester pools to nothing more than a staging URL.

Android

01
Emulate locally

Run the app across virtual devices and API levels in Android Studio's built-in emulator.

02
Automate at scale

Run instrumented tests across real hardware profiles with Firebase Test Lab.

03
Internal testing track

Push a build to up to 100 internal testers via Play Console for a fast sanity check.

04
Closed testing (mandatory)

Personal accounts must run a closed test with at least 12 opted-in testers for 14 continuous days before production access unlocks.

iOS

01
Simulate locally

Run the app in Xcode's Simulator across iPhone, iPad, and OS version combinations.

02
Device testing

Install signed debug builds on physical devices to catch hardware-specific issues (camera, sensors, performance).

03
Internal TestFlight

Distribute to up to 100 internal testers immediately after upload — no review needed.

04
External TestFlight

Once a build clears a lightweight beta review, invite up to 10,000 external testers before submitting for full review.

Mobile Web

01
Responsive checks

Test breakpoints and touch targets in Chrome DevTools' device-emulation mode.

02
Audit performance

Run Lighthouse for performance, accessibility, and PWA-installability scores.

03
Cross-browser pass

Verify real rendering across iOS Safari and Android Chrome with BrowserStack or Sauce Labs.

04
Staging deploy

Push to a staging subdomain for a final walkthrough — no external gatekeeper required.

03

Publishing, step by step

From a finished build to something a stranger can open on their own phone.

Android

01
Build the release AAB

Generate a signed Android App Bundle with Gradle.

02
Complete the store listing

Add screenshots, description, content rating questionnaire, and the Data Safety form in Play Console.

03
Roll out

Release to a staged rollout percentage or straight to 100% of users.

04
Automated + policy review

Google's review is largely automated; most listings go live within hours to a couple of days.

iOS

01
Archive and sign

Create a distribution build in Xcode signed with an App Store certificate and provisioning profile.

02
Upload via Transporter

Push the .ipa to App Store Connect through Xcode Organizer or the Transporter app.

03
Submit for review

Fill in metadata, screenshots, privacy “nutrition label,” and reviewer test credentials, then submit.

04
Human review

A person reviews the app against the App Store Review Guidelines — typically 2–5 days in 2026, longer at peak submission periods.

Mobile Web

01
Build for production

Bundle and minify the app; generate the web app manifest and service worker for PWA installability.

02
Deploy to hosting/CDN

Push to a host with HTTPS enabled — Vercel, Netlify, Cloudflare Pages, or your own infrastructure.

03
Point the domain

Update DNS; the new version is live the moment it propagates.

04
Optional: wrap for a store

Package the PWA as a Trusted Web Activity for Google Play, or list it in the Microsoft Store — each then follows that store's own review.

Publishing rights & requirements

What you have to agree to, register, or hold before you're allowed to distribute.

ANDROID · GOOGLE PLAY

  • $25 one-time registration fee, no renewal, unlimited apps under one account.
  • Accept the Google Play Developer Distribution Agreement.
  • Personal accounts require passing the 12-tester / 14-day closed test before production.
  • Organization accounts require a D-U-N-S number for business verification.
  • Complete the content rating (IARC) questionnaire and Data Safety disclosure.
  • Commission: 15% on the first $1M/year in-app revenue, 30% above that.

IOS · APPLE APP STORE

  • $99/year for the Apple Developer Program (individual or organization).
  • Accept the Apple Developer Program License Agreement and, for paid apps, the Paid Applications Agreement.
  • Organization accounts also require a D-U-N-S number.
  • Apps must pass human review against the App Store Review Guidelines.
  • $299/year Enterprise Program exists only for internal-staff distribution, no App Store review.
  • Commission: 15% under the Small Business Program (revenue under $1M/year), 30% above.

MOBILE WEB · BROWSER / PWA

  • No platform account or fee — you own the domain, so you own the terms.
  • Requirements are self-imposed: HTTPS, a valid web app manifest, and a service worker if you want installability.
  • No revenue share — payments run through whatever processor you integrate directly (e.g. Stripe).
  • If you later wrap the PWA for a store (Trusted Web Activity, Microsoft Store), that store's fees and agreements then apply on top.
  • You're still bound by general law — privacy regulations (GDPR/CCPA), accessibility standards, and payment-industry rules.
